# xAI推出Grok Bot：可以长期驻留云端的AI助手

> 原文链接：[https://www.laoshoucun.com/grokdt/2481](https://www.laoshoucun.com/grokdt/2481)

<p>xAI 在 Grok 4.6 之后又落一子：Grok Bot，一个常驻云端的 AI 助手。它不在对话框里等你提问，而是直接驻进你的远程开发环境，长期运行、主动干活。设想一下这个画面：晚上睡前布置好任务，早上醒来代码已经提交进仓库，等着你 review，Grok Bot 要交付的就是这种日常。</p>
<p><img decoding="async" src="https://cdn.laoshoucun.com/web/2026/08/20260817113619_344501.png" alt="xAI推出Grok Bot云端助手"></p>
<h2>不是随叫随到，是住下来</h2>
<p>常规 <a href="https://www.laoshoucun.com/grok" target="_blank" rel="noopener">Grok</a> 聊天机器人的逻辑是一问一答，窗口一关记忆清零。Grok Bot 把这套逻辑整个反过来：上下文长期保留，没有新指令时也能自主推进，设定目标后，拆解步骤、调用工具，执行操作全由它自己完成，人不必在场。</p>
<p>适合它的活也很明确：需要跨时间推进的多步骤任务。监控数据流、周期性报告生成，代码库自动化维护，这些以前要靠人轮班盯梢调度系统的工作，现在可以整个交给一个不需要睡觉的&#8221;住户&#8221;。</p>
<p>这个方向上各家其实都落了子：Claude Code 做后台任务，OpenAI Codex 有 Cloud 模式，Cursor 在往 Agent 化走。共识是同一个：AI 的下一形态不是我问我答，是我替你值守。Grok Bot 的差异点在底座，运行于 Grok 4.6 之上，500K 上下文加长时程 Agent 优化，长任务跑再久，背景信息也不怕溢出丢失。</p>
<h2>61 分的底座，接得住长任务</h2>
<p>常驻型 Agent 最大的风险是&#8221;久跑变形&#8221;：前期步骤利落，越往后越不靠谱，这考验的正是底座推理能力。Grok 4.6 在 Artificial Analysis 智能指数得 61 分，与 GPT-5.6 Sol 并列，站的是第一梯队。有分数垫底，长任务才敢接。</p>
<h2>三个冷静的提醒</h2>
<p>眼下它离&#8221;即开即用&#8221;还有距离。第一，平台覆盖窄，仅支持 Cursor、Grok Build 等少数环境，不是哪儿都能住。第二，最长连续运行时长官方没公布，久跑稳定性待验证。第三，账单要算，计费与 Grok 4.6 API 相同，输入 2 美元每百万 token、输出 6 美元每百万 token。按量计费叠上全天候运行，费用会随时间累积，托管前务必先估成本。</p>
<h2>上车前先回答两道题</h2>
<p>Grok Bot 的发布透露了 xAI 的盘算：不只卖模型，还要做应用平台，把模型包装成持续干活的&#8221;住户&#8221;，身份就从被调用方变成产出方。对用户，动手前先想清楚两件事：常驻账单怎么控制，任务授权的边界画在哪。这两个问题的答案，比&#8221;哪个模型更强&#8221;更决定使用体验。</p>
